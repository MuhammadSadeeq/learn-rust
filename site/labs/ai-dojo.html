Agent Code Review Dojo

Read Rust that an AI agent wrote, flag the lines a senior reviewer would question, then compare your review with the version you would merge.

Best after Chapter 12. The last few cases need Chapters 18 to 21.

Each case is a short program an agent wrote for a task. Click or tap each line you would question, then submit. You score on the smells you found and on the false flags you raised, so flag what a careful reviewer would question, and nothing else.

Bug
Wrong or unsafe at runtime.
Performance
Needless copies, allocations or passes.
Idiom
Compiles, but is not how Rust is usually written.
Design
An API or function shape that will hurt later.

Keyboard: Tab moves between line numbers, and Enter or Space flags a line.

After the dojo

Prompting playbook

An agent is good at making code compile and making the one test it was shown pass. It is less likely to ask whether the code is the code you would merge. Most of the smells in this lab are cheap to prevent in the prompt, and expensive to find in review.

  • Name the versions. Say which crate and which version to use, such as tokio 1 with the full feature set. An agent that does not know the version guesses, and guessed APIs are a common reason code fails to compile.
  • Ask for evidence, not a summary. Ask it to run cargo fmt, cargo clippy --all-targets -- -D warnings and cargo test, and to paste the last lines of each. "Make sure it is clean" gets a yes. Pasted output is something you can check.
  • Set the error policy first. Libraries return typed errors, and binaries may use anyhow. Without that rule, agents reach for unwrap() and Box<dyn Error>, because those make the code compile fastest.
  • Ask it to justify each clone. After the feature works, ask it to list every clone() and to_string() in the diff, and to say why each one needs an owned copy. An agent that has to justify a clone usually removes it.
  • Put the rules in the repository. A CLAUDE.md or AGENTS.md file applies to every session. A rule typed once into a chat applies to that one chat.
  • Review the diff, not the summary. The summary says what the agent meant to do. The diff shows what it did. Read the diff first, and use the smells in this lab as your checklist.
CLAUDE.md or AGENTS.md
# Rust rules for this repository

## Before you finish
- Run `cargo fmt --all`.
- Run `cargo clippy --all-targets -- -D warnings` and fix every warning. Do not add `#[allow]` to hide one.
- Run `cargo test` and make sure it passes.
- In your final message, paste the last lines of each command.

## Errors
- No `unwrap()` or `expect()` outside tests and `main`.
- Libraries return typed errors built with `thiserror`. Binaries may use `anyhow`.
- Never ignore a `Result`. Propagate it with `?`, or handle it and say why.

## Borrowing and types
- Take `&str` and `&[T]` parameters, not `&String` and `&Vec<T>`.
- Clone only when an independent owned value is needed, and say why in a comment.
- Model states as enums, not strings.

## Async
- No blocking calls inside `async fn`: no `std::thread::sleep`, no `std::fs`, no blocking locks. Use the async version, or `spawn_blocking`.
- Never hold a `Mutex` or `RwLock` guard across `.await`.

## Unsafe
- Every `unsafe` block needs a `// SAFETY:` comment that names the invariant it relies on.

## Dependencies
- Pin crate versions in `Cargo.toml`, and name them in your summary.
