Why Rust, and why now

Rust compiles to native machine code, the same kind of code C and C++ produce, and it has no garbage collector. Nothing pauses your program to hunt for memory it no longer uses. The compiler also checks memory safety before the program runs. Whole classes of bugs, such as use after free, double free and data races between threads, fail to compile instead of failing in production.

The rules that keep memory safe also keep threads from changing the same data without coordination. You will meet that in Chapter 18. Rust also ships one toolchain for compiling, testing, formatting, linting and managing dependencies, so you use the same few commands in every project.

There is a second reason this matters now. AI agents write a lot of code, and they write it quickly. In Rust the compiler and the tests reject a whole category of mistakes before the code runs, which makes agent-written code much easier to verify. It is one reason more runtimes, command-line tools, web frameworks and agent harnesses are being written in Rust.

For you, this means you will often read and review Rust written by an agent, more often than you write Rust from a blank file. Review starts with the compiler's verdict, but a program that compiles can still do the wrong thing. Ask whether the code does what you meant, and whether its ownership choices are the ones you would make. This course trains both skills: writing small programs, and reading code you did not write.

Rust has a real learning curve. The hardest part is ownership, which you reach in Act II. This course flattens that curve on purpose: every concept gets a picture you can step through, you predict before each reveal, you check your guesses against the real compiler, PHP bridges show where the comparison breaks, and Forge quests and recall cards keep it in your head.

Think first: your PHP app is fast enough today. Name one good reason to write part of it in Rust anyway.

Some good reasons: a CPU-heavy step that dominates response time, a long-running worker that must keep its memory small and predictable, a command-line tool you want to ship as one file that needs no PHP on the target machine, or a tool an agent will run constantly, where a compile-time check is worth having.

Interpreted per request vs compiled once

PHP is usually called an interpreted language. In practice it compiles your source to opcodes, the internal instructions that the Zend engine executes. Rust works differently in one important way: it compiles everything ahead of time, before anyone sends a request.

In a classic PHP-FPM setup, the web server hands each request to a PHP worker process. PHP loads the script and compiles it to opcodes. OPcache keeps those opcodes in shared memory, so the compile step is usually skipped after the first request. The script then runs. When the response is sent, PHP frees everything the request allocated. The worker process lives on for the next request, but nothing from the last request is still in memory.

A Rust web service is built once, before you deploy. cargo build compiles the whole program into one native binary. You start that binary and it keeps running. Each request is handled by code that is already machine code, so nothing is compiled when a request arrives. The process also keeps whatever your program stores in memory, until your code removes it.

The PHP lane repeats its setup for every request. OPcache can skip only the compile step, and the script still runs and is torn down each time. The Rust lane compiles once, before deploy, and one running process handles every request. Switch OPcache off to see the compile step come back for each request. The lanes show the order of the work, not how long each step takes.

With OPcache on, what does PHP still do on every request?

  1. Re-parse the source file from disk.
  2. Execute the opcodes, then tear down the request's memory.
  3. Compile the script to machine code.
  4. Nothing. The whole response is cached.

OPcache skips the parse and compile-to-opcodes step, which is the expensive part. Executing the opcodes and freeing the request's memory still happen on every request. OPcache caches compiled code, not responses. Machine-code compilation is not the usual PHP request path, so that option is wrong too.

If you have run Laravel Octane on Swoole, RoadRunner or FrankenPHP, you have seen the long-running model already. The application boots once and serves many requests. The catch is that anything you leave in memory survives into the next request.

Rust has the same property. The difference is that the compiler makes you say who may touch shared state, and when.

Install Rust

Rust is installed with rustup, a toolchain manager. On macOS or Linux, run this in a terminal:

curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

On Windows, download rustup-init.exe from rustup.rs and run it. Rust uses Microsoft's linker on Windows, so the installer may offer the Visual Studio C++ Build Tools. Install them if it asks.

Open a new terminal, so it loads the updated PATH, and check the install:

rustc --version
cargo --version

To upgrade later, run rustup update. It updates the toolchain you have.

Think first: you just installed Rust, but a new terminal says rustc: command not found. What is the most likely cause?

The terminal was open before the install, so it does not know about the directory rustup put the tools in. rustup adds ~/.cargo/bin to your PATH through your shell profile, and a shell only reads that when it starts. Open a fresh terminal. In the current one, . "$HOME/.cargo/env" also works.

Cargo: Composer and Artisan in one

Cargo creates projects, builds them, runs them, runs tests, fetches dependencies and formats code. Start a project with cargo new, then run it:

cargo new hello
cd hello
cargo run

The first cargo run prints something like this. Your path will differ:

   Compiling hello v0.1.0 (/path/to/hello)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.14s
     Running `target/debug/hello`
Hello, world!

Cargo compiled the program, then ran the binary it produced. The dev profile is the default debug build. Every later cargo run skips work that is already done, and only rebuilds what changed.

Anatomy of hello world

Here is the program cargo new generated. Run it in the browser, then read it one token at a time.

fn main() {
    println!("Hello, world!");
}

Tap a token

()

fn declares a function.

The name comes next, then the parameter list in parentheses, then the body in braces. Every function in Rust is written this way.

<?php
echo "Hello, world!\n";
fn main() {
    println!("Hello, world!");
}

PHP runs statements from the top of the file down. Rust has no top-level code. Execution starts in main. Everything else in a Rust file is a declaration, such as a function, struct or constant, rather than a statement that runs.

What does the ! in println! tell you?

  1. It is a macro, and the compiler expands it into other code before the program is built.
  2. It is the logical NOT, so the line runs only when a condition is false.
  3. It marks the call as unsafe, so the compiler skips its checks.
  4. It sends the output to standard error instead of standard output.

println! is a macro, and so is vec!. A macro is code that writes code. The ! is how you spot one at the call site. Macros take a variable number of arguments, which a normal function cannot, and println! checks its format string when you compile. You will write your own macros in Chapter 21.

Printing values

println! takes a format string. Each {} placeholder is filled by the next argument, and the compiler checks the placeholders against the arguments before the program runs.

The examples below use let to give values names. let name = value; gives a value a name. Chapter 02 explains it, and why a plain let cannot be changed.

fn main() {
    let name = "Ferris";
    let legs = 10;
    let price = 3.5;
    println!("{name} has {legs} legs");
    println!("{} has {} legs", name, legs);
    println!("[{:>8}] [{:<8}] [{:^8}]", name, name, name);
    println!("price: {price:.2}");
    println!("{:?}", (name, legs));
}
PlaceholderWhat it doesOutput for name = "Ferris"
{}Display format, meant for people. The next argument fills it.Ferris
{name}The same, but the variable is named inside the braces.Ferris
{:?}Debug format, meant for developers. Strings get quotes."Ferris"
{:>8}Right-aligned in eight columns. {:<8} left-aligns, {:^8} centers. Ferris
{price:.2}Two digits after the decimal point.3.50
{n:02}Pads a number with zeros to a width of two.05 for n = 5

PHP's printf uses placeholders such as %s and %05.2f. Extra arguments are silently ignored, and a missing one throws an ArgumentCountError only when that line runs. In Rust the placeholders are checked against the arguments at compile time, so println!("{} {}", 1) with one argument is a compile error.

{} only works for types that implement Display. A tuple does not, so this fails to compile:

fn main() {
    let name = "Ferris";
    let legs = 10;
    println!("{}", (name, legs));
}

Use {:?} for a tuple.

println! prints the text. format! takes the same format string and gives the text back as a String, so you can keep it in a variable or return it from a function. Chapter 08 covers String. The placeholder {:02} pads a number with leading zeros to two digits, so format!("{:02}", 7) is 07.

Comments use the same forms as PHP's // and /* */. A /// comment is a doc comment. It documents the item below it, the way PHPDoc sits above a method.

fn main() {
    // A line comment runs to the end of the line.
    /* A block comment
       can span several lines. */
    println!("comments cost nothing at run time");
}

cargo doc --open turns your /// comments into a browsable HTML site. In a library crate, code blocks inside them are compiled and run by cargo test, so the examples in your docs stay correct. A binary project like this one does not run them.

What does this print?

fn main() {
    println!("[{:>4}] {:.1}", 7, 2.0 / 3.0);
}
  1. [7   ] 0.7
  2. [   7] 0.7
  3. [   7] 0.66
  4. [7] 0.7

{:>4} right-aligns the first argument in a field four characters wide, so 7 gets three spaces in front of it. {:.1} rounds the second argument to one digit after the decimal point, so 0.666 becomes 0.7. Both formats apply to the same line.

Make this print Hello, Ana! by putting the variable inside the string, not as a second argument.

fn main() {
    let name = "Ana";
    println!("Hello, [[{name}]]!");
}

{name} reads the variable name directly. The name in the braces has to match a variable in scope exactly. A typo there is a compile error, not an empty string in your output.

Your first compiler error

Now break the program on purpose. This version forgets the !:

fn main() {
    println("Hi");
}

Here is what rustc prints for it. Read it from the top:

error[E0423]: expected function, found macro `println`
 --> src/main.rs:2:5
  |
2 |     println("Hi");
  |     ^^^^^^^ not a function
  |
help: use `!` to invoke the macro
  |
2 |     println!("Hi");
  |            +

error: aborting due to 1 previous error

For more information about this error, try `rustc --explain E0423`.

  1. The code and the summary. error[E0423] is a stable code you can look up. The text after it says what went wrong.

  2. The location. The arrow --> gives the file, line and column where the problem starts.

  3. The source excerpt. The ^^^ marks the exact tokens at fault, and the label beside them says why.

  4. The help line. help: often gives the fix. Here it suggests adding the !.

  5. The long explanation. rustc --explain E0423 prints a fuller description of any error code.

The compiler is your pair programmer. Its messages are specific, and they usually name the fix. Read the help: line before you search the web for the error.

Does this compile?

fn main() {
    let total = 3;
    println!("{totl}");
}
  1. Yes. It prints 3, because the name is close enough.
  2. No. totl is not a variable in scope. This is error E0425.

The name in the braces must be a variable in scope, and totl is a typo for total. The compiler even suggests the fix. In PHP, a typo in a variable name becomes an "Undefined variable" warning that appears only when that line runs. In Rust it is caught before the program exists.

    Complete the program so it prints 7. Pick the macro that builds the text and gives it back.

    fn main() {
    let name = "Ana";
    let greeting = [[format!|println!]]("Hi, {name}");
    println!("{}", greeting.len());
}

    format! builds a String and returns it, so greeting holds Hi, Ana, and its length is 7. println! prints the text and gives back nothing, so greeting would be (), and greeting.len() would not compile.

    How to use this course

    Each chapter works the same way. You read and interact in the browser, then you write code in your editor, and cargo forge checks it with the real compiler, rustc.

    1. Clone the repo.

      git clone https://github.com/MuhammadSadeeq/learn-rust.git
cd learn-rust

    2. Open the course. Serve the site folder and visit it in your browser, or open site/index.html directly.

      python3 -m http.server -d site 8000

      cargo forge            # watch mode: your next quest, rechecked on every save
cargo forge hint       # a hint for the current quest
cargo forge list       # every quest, with your progress

    A note on names: the Forge, the character, stands for the Rust compiler, rustc. cargo forge is this course's practice tool; it runs the real compiler and the tests for you.

    Each chapter lists its quests near the end. Tick passed in forge next to a quest to record it on the site.

    On the chapter pages you will see quizzes that award XP, Think first blocks that hide the answer until you have guessed, Memory X-Ray step-throughs that show a program running, and recall cards at the end.     Hello, Crab

    • Rust compiles ahead of time. cargo build produces a native binary, and a running process handles requests with no compile step. PHP compiles per request unless OPcache has the opcodes cached, and it frees request memory when the response is sent.
    • rustup installs and switches toolchains. rustc compiles. cargo builds, runs, tests and manages dependencies.
    • Execution starts in fn main. println! is a macro whose format string is checked at compile time: {} for Display, {:?} for Debug, and {name} to use a variable inside the string.
    • Read a rustc error from the top: the code and summary, then the --> location, the ^^^ marker, and the help: line.
    • cargo check is the fastest feedback the compiler gives. target/ holds build output, and you never edit or commit it.

    One good answer: "Rust compiles the whole program ahead of time with cargo build, into one native binary. The server starts that binary once and keeps it running, so each request runs machine code that already exists, and nothing is compiled when a request arrives."
